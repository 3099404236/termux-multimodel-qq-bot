# 桌面悬浮球

一个常驻桌面最上层的小球。默认左半边跟着手机机器人链路状态走；安装
ProgressRadar 私有备份后，右半边同时显示最近一次备份状态。

    双击 stack-ball.vbs

## 颜色

| 颜色 | 含义 |
| --- | --- |
| 绿 | 机器人在正常回复。中间重试过几次不算故障，发出去了就是绿的 |
| 红 | 有人提问但什么都没收到 |
| 灰 | 球自己连不上监控（手机不在线，或者两条路都断了） |
| 蓝 | 私有备份正在运行 |
| 黄 | 最近一次备份成功，但成功记录已经超过预期间隔两倍 |

判定规则完全来自监控自己的 `status.json`，这边不重复实现，改规则只需要改手机那一处。

## 操作

- **单击** — 打开完整状态面板（打不开时看日志 `%LOCALAPPDATA%\stack-ball.log`）
- **悬停** — 显示每条链路的详情
- **拖动** — 换位置，松手就记住（存在 `%LOCALAPPDATA%\stack-ball-position.txt`）
- **右键** — 立即刷新 / 打开面板 / 立即运行私有备份（配置后出现）/ 退出

## 私有备份集成

备份安装器会写入 `%LOCALAPPDATA%\stack-ball-sources.json`。悬浮球从该文件读取：

- `backup_status_file`：备份任务原子写入的状态 JSON；
- `backup_panel_url`：单击悬浮球时打开的本机综合状态页；
- `backup_task_name`：右键“立即运行私有备份”启动的 Windows 计划任务；
- `interval_hours`：判断成功记录是否过期的计划间隔。

没有这个配置时，悬浮球仍可独立监控机器人，右半边显示灰色。配置存在时，提示框会同时列出
机器人链路与备份结果；本机综合面板默认在 `http://127.0.0.1:8788/`。

## 连接

按顺序试两个地址，哪个通用哪个，失败自动换另一个：

1. `http://192.168.3.243:8799` — WiFi 直连，**拔掉数据线也能用**
2. `http://127.0.0.1:8799` — 走 adb forward，需要 USB 连着

每次轮询都从第一条开始试，失败立刻换下一条，所以哪条路恢复了都能马上用上。
手机换了 WiFi 网段的话改 `stack-ball.ps1` 顶部的 `$Script:Urls`。

### 球变灰的真实原因（2026-08-02 查证）

**手机的 DHCP 租约自己从 .243 变成了 .246**，跟拔不拔 USB 无关。当时的误判过程值得记：

- 拔线后球变灰，第一反应是"安卓 Doze 休眠切了 WiFi"——**错的**。
  插回线一查：`wifi_sleep_policy` 本来就是 2（永不休眠），移动数据是关的，
  机器人一直走的 WiFi。用户当场就说"绝对没休眠，我刚还跟他聊得好好的"。
- 那为什么扫全网段也没找到？因为**扫描本身被代理骗了**，见下。

所以球不再写死 IP：记住上次可用地址，两条路都断就扫本机所在的 /24，
找到就缓存。实测从"缓存的是错地址 + adb forward 也拆了"到重新连上，用了 3 秒。

### 分层窗口的两个坑

- **右键不会自动弹菜单**。分层窗口从不被激活，系统不给它发 `WM_CONTEXTMENU`，
  所以光设 `Form.ContextMenuStrip` 没用，必须在 `MouseUp` 里自己
  `$Menu.Show([Cursor]::Position)`。
- **WinForms 会静默吞掉 PowerShell 事件处理器里的异常**。原来 `MouseUp` 里
  先写位置文件再开面板，写文件偶尔失败就把整个点击吃掉了——实测 3 次点击只有
  1 次能打开。改成只有真拖动才写位置，并给整段加 try/catch 记日志，之后 3/3。

### 两个网络层面的坑

- **必须禁用系统代理**。这台机器上跑着 TUN 模式的代理（`XiGua` 网卡，198.18.0.1/30），
  它会劫持到手机的连接：TCP 握手"成功"了（其实是代理本地假接受），数据却永远回不来。
  所以 `Test-NetConnection` 会骗你说端口开着。`TimedWebClient` 里显式设了 `Proxy = null`。
- **`WebClient` 没有超时属性**，默认等 100 秒。碰上上面那种假连接，球会在过期颜色上
  卡一分半。所以派生了 `LanWebClient` 覆写 `GetWebRequest` 设 6 秒超时。
- **光设 `Proxy = null` 不够**。TUN 模式代理是按*路由*抢流量的，跟 WinINET 的代理设置
  无关（`192.168.*` 明明在绕过列表里也照抢）。必须用 `ServicePoint.BindIPEndPointDelegate`
  把源地址钉在拥有该网段的网卡上，包才会真的从以太网出去。
- **端口开着不等于是我们的服务**。代理会对它那个网段的每个地址都完成 TCP 握手，
  所以扫描第一次扫出来的是 `198.18.0.250`（代理自己）。现在扫到端口后还要再请求一次
  `/status.json` 并确认里面有 `overall` 和 `links` 才算数。
- **扫描不能用 `Task.Run` + 阻塞等待**。500 多个探测各占一个线程池线程，而线程池每秒
  只增长约两个，绝大多数探测在超时窗口内根本没轮到执行，结果报告"没找到手机"。
  改成 `Socket.BeginConnect` 重叠 I/O 后 3 秒扫完。
- **`.ps1` 只能有一个 BOM**。反复用"读出来再写回去"的方式修编码会把 BOM 越叠越多，
  叠到三个时脚本还能跑，但**顶层的 `$Script:Colors = @{...}` 赋值会静默失效**，
  表现为运行期"无法对 Null 表达式调用方法"。排查了好几轮才定位到。

## 快捷方式

已经在开始菜单放了一个叫 **穿制服** 的快捷方式（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\穿制服.lnk`），
Windows 搜索栏里搜这三个字就能点开。想改名直接改这个 .lnk 的文件名即可。

重复点击不会开出第二个球——脚本开头用一个命名 Mutex 挡住了。

## 开机自启

把 `stack-ball.vbs` 的快捷方式丢进 `shell:startup`（Win+R 输入这个就能打开那个文件夹）。

## 两个实现上的坑

- `.ps1` 必须存成 **UTF-8 带 BOM**。PowerShell 5.1 读 `.ps1` 默认按系统 ANSI（中文机器上是 GBK），
  不带 BOM 的话文件里的中文会全部乱码并直接导致语法错误。
- 圆球用 `UpdateLayeredWindow` 画，不是 `Form.Region`。Region 裁出来的圆边缘是锯齿的；
  分层窗口吃带真实 alpha 通道的 32 位位图，边缘和光晕才能跟桌面背景平滑融合。
